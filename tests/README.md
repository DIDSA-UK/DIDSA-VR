# Headless tests

Godot scripts that exercise the interaction code without a headset, GPU or
backend. They print `SMOKE ...` lines rather than pass/fail, so compare
against the expected values below. `run_all.sh` runs the lot and fails on any
script or parse error; `ci.sh` (what CI runs) additionally fails on any
assertion that prints `false` (see "CI" below).

```
GODOT=/path/to/godot tests/run_all.sh        # from the project root (it points the settings at its own file, DIDSA_SETTINGS_PATH, and resets it before every test)
"$GODOT" --headless --path . --script res://tests/grab_and_scale.gd    # one test
```

**One at a time:** every test shares the app's one `user://` folder (settings, recent file, servers list), so two Godot test runs at once corrupt each other's state: run them one after another. **A fresh checkout has no import cache** (CI does not run `--import`): a test must not `load()` an imported asset such as a `.glb` scene (read the raw file with `GLTFDocument`, as `scripts/landing/didsa_logo.gd` does); check with a copy of the tree that has no `.godot/` folder.

**Landing:** `main.gd` starts on the landing (logo, rocket garden, launcher) unless `landing_enabled` is false, and its default is false
when the environment variable `DIDSA_NO_LANDING` is set. `run_all.sh`, `ci_e2e.sh` and `ci_render.sh` set it, so every test sees the old start
(no landing; with a backend, the start-up import the `e2e_*` tests wait for). **Running an `e2e_*` test by hand needs
`DIDSA_NO_LANDING=1` too**, or it waits for an import that never starts. `tests/landing.gd`, `tests/tips_reel.gd` and `tests/landing_render.gd`
set `main.landing_enabled = true` themselves and use their own settings and recent-file paths (`DIDSA_SETTINGS_PATH`, `DIDSA_RECENT_PATH`, `DIDSA_SERVERS_PATH`).

**Safety:** any test that instantiates `scenes/main.tscn` must first set
`main.secrets_file_path` to a nonexistent file (as `tablet_scene.gd` does),
otherwise `main.gd` reads the real `secrets.cfg` and POSTs to the configured
backend. Also `await process_frame` after `add_child(main)` before looking up
its nodes (its `_ready` is deferred) — this isn't specific to `main.tscn`:
any bare `Node3D` a test builds by hand (a stand-in "hand", a gizmo) needs
the same one-frame wait after `get_root().add_child(...)`/`root.add_child(...)`
before its `global_position`/`global_transform` can be read or written at
all — `is_inside_tree()` is still false immediately after `add_child()`
inside a `SceneTree`-extending `--script`'s own `_initialize()` (unlike
`add_child()` during normal gameplay, which takes effect synchronously);
found the hard way writing `tests/section_tool.gd` (see that test's own
top-of-file note for the minimal repro).

**What headless can't do:** fake a real grip press (call the routine directly,
e.g. `two_hand_model._update_one_hand(hand, pos)`), render for real, or judge
feel. Say what you couldn't verify.

## CI

`.github/workflows/headless-tests.yml` runs on every push and pull request that touches `scripts/`, `shaders/`, `scenes/`, `tests/`,
`project.godot` or the workflow itself, and **weekly** (Monday). It also checks DIDSA-CAD `main` out into `didsa-cad/` and sets
`DIDSA_CAD_DIR`, so the seven copied fixtures (`tests/fixtures/README.md`, "Copied from DIDSA-CAD") are compared with the source and a CAD-side
change fails the job (before, a run with no checkout printed "no source" and passed).

**Whole lines, and silent tests.** `run_all.sh` and `ci_e2e.sh` hand `check_smoke.py` every SMOKE line **uncut** (they used to cut each to 200 characters first, so a
long label's trailing `false` could never fail CI); `ci.sh` and `ci_e2e.sh` cut only the console echo. `SMOKE_CUT=200 tests/run_all.sh` cuts for reading by hand. A test
that exits non-zero (124 = timed out) or prints no SMOKE line gets a `NOTE <test>: exit code N, last 30 lines of its output:` block in the log, where it used to leave nothing.

**How the assertions are checked.** The tests print `SMOKE <what>: <value>` and exit 0, so `tests/check_smoke.py` reads the captured log (the
`== <test>` headers `run_all.sh` prints, then each test's SMOKE lines) and fails when:
- a SMOKE line ends in `false` (or its value starts with `false`) and is not in `tests/expected_false.txt`;
- a `SCRIPT ERROR` / `Parse Error` / `FAIL <test>` line appears;
- a test printed no SMOKE lines at all (unless its name is in `tests/no_smoke.txt`, empty on purpose).

Baseline entries that no longer print `false` are reported as stale warnings (never failures): delete them. Note this also means an
*expected* false that flips to `true` is only a warning. The checker reads booleans only: a line that prints a number you are meant to eyeball
(steadiness, sensitivity, timing tables) is not machine-checked, and a `false` in the middle of a line (`... true (pressed=false)`) is
informational. `tests/check_smoke_selftest.py` tests the checker itself.

**Adding a test.** Add it to the `for t in ...` list in `run_all.sh` and make every assertion a `print("SMOKE <what>: ", <bool>)` line, true when
correct. Never print a *false* for the good outcome. If a line must print `false` when the code is right (an informational state such as
"panel rendering after close: false"), add `<test> | <SMOKE text up to the first ": ">` to `tests/expected_false.txt` with a comment saying why.

**Updating `expected_false.txt`.** Run `GODOT=... tests/ci.sh`; each `FAILURE ... unexpected false` line is either a regression (fix the code) or
a new intended false (add it, with a comment). Do not add an entry just to get green. To run the checker on a saved log:
`python3 tests/check_smoke.py run.log --baseline tests/expected_false.txt --no-smoke tests/no_smoke.txt`.

## Timing is reported, never a gate

A test that fails because a machine was slow is a false positive: CI reruns of the same commit pass. So no test here decides pass or fail on elapsed time. `SMOKE BENCH ...` lines (and the per-frame cost lines in `local_retraction.gd`, `limit_mates.gd`, `design_table_perf.gd`) print their numbers and nothing more. DIDSA-CAD does the same (`backend/tests/timing.py`, `client/test/support/timing.dart`: the measurement is printed, enforced only with `DIDSA_ENFORCE_TIMING=1`, and a backend test fails if one is added that gates on time). What a timed step is really about should be asserted by something deterministic (a status, a count, a result).
