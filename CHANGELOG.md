# Changelog

Newest first. Dates are 2026. Labels (Milestone, Phase, R-number) are the ones used in older docs and commit messages.
"Verified" means headless, software-render or real-backend tests unless a headset is named. Headset testing is ongoing and informal and is not recorded per feature here. See `docs/status.md`.

## Branch `claude/gears-and-motion` (22 Oct, not merged; plan: `docs/gears-and-motion-plan.md`)

- **Gears that move together** (M1-M7; needs the DIDSA-CAD backend on the same branch). Headless- and live-backend-tested; not checked on the headset.
  - **Gear bore** (M1/M2): an optional centre bore on spur, helical and bevel gears, not internal ones (backend `bore_diameter`, the flat app's field, the design table's gear tools).
  - **Gear, Rack and pinion and Screw mates** (M3-M5): the mates tool, the tablet and the wheel make them from two axis picks (empty value = Auto from the teeth); turning one part turns the other. Reverse / Left-hand, list rows such as "1 : 2".
  - **Constraint model version 5** (M6): the motion model carries the coupler rows (analytic, relative to the pose a solve started from); Dart and GDScript read it and match the shared golden vectors.
  - **Drive tool** (M7): `scripts/drive_tool.gd`. Pick a round face (turn) or a straight edge (slide) of a mated part on the tablet's Assemble page or the wheel's new **Drive** wedge; the right stick sets the speed (30 rpm at full, 60 rpm cap), A keeps it running, B stops; the whole run is one undo step, and a readout lists every turning part's rpm. The wheel's root ring has eleven wedges now. Tests: `drive_tool`, `e2e_drive`. Not tried on a headset: speed feel, frame rate, smoothness over Wi-Fi.

## Branch `claude/appearance-and-scenes` (19-20 Oct, not merged)

- **Finding moved files** (20 Oct; DIDSA-CAD `docs/moved-files-scope.md` F2; needs the DIDSA-CAD backend on the same branch for `ref_part_id`). Headless- and live-backend-tested; not checked on the headset.
  - **When a part file has moved** (to a subfolder, or renamed outside the app), opening the assembly finds it by the part id its occurrence remembers (`ref_part_id`; an older file's stored `resolved_part_id`) in an index of the opened file's folder, the project folder and the models folders, every subfolder included (`scripts/file_index.gd`, built only when a reference misses; ids cached per file). One file with the id is used: the status line names the move, the corrected path goes into the session and is an unsaved change, so Save as new file writes it. The rule is `scripts/file_lookup.gd`, a copy of DIDSA-CAD's reference, checked against its 16 golden vectors.
  - **Never a silent swap:** two files with the id, a different part now at the path, or only a same-name file elsewhere load nothing for that reference; it is listed with its candidates. A reference with no id whose file is at its path loads as before.
  - **Files > References** (new tablet page): what was found in a new place, and each reference to review with why, its candidates (Use opens the assembly again with the pick; a file that is not the placed part needs a second press), **Locate...** (every model file in the searched folders) and **Leave missing**. A pick re-opens the assembly; when the only unsaved change is a corrected path it doesn't ask first.
  - **Not done:** picks for a file added with Add or into a room (those only report on the status line); the index is capped at 5000 files and 12 folders deep.
- **Scenes in VR** (DIDSA-CAD `docs/scenes-scope.md` S2; needs the DIDSA-CAD backend on the same branch, `/parts/{id}/scenes`). Headless- and live-backend-tested; not checked on the headset.
  - **On the sandbox** (`scripts/scenes_tool.gd`): **Show** relaxes the mates and poses every placed instance by the scene (`scripts/appearance/scene_compose.gd`, a copy of DIDSA-CAD's reference checked against its 6 golden vectors), hides what it hides (a hidden part can't be lasered) and puts its looks on top of the model's; anything moved or painted then is temporary. **Update scene** and **Save as new** (named on the keyboard) write what is on screen as overrides against the real model: a moved pattern copy by its path, a group move of a sub-assembly's parts as one override on the sub-assembly, a paint as an appearance override. The root's own content can't move in a scene and a paint on every copy / placement has no scene form: both are left out with a note. **Back to default** is Return parts; when the shown scene has unsaved changes it asks **Update / Discard / Stay** first (the Scenes page, the Mates page's Return parts and the wheel's Return pill all ask); the plain sandbox still returns without asking.
  - **Viewpoint:** View on Show turns and places the model so you look from the scene's eye toward its target, at the scale you have (it never zooms); Save my view keeps where you look from with a new scene.
  - **Where:** the scenes of the world's assembly and of each open room's Part. Tablet: **Assemble > Scenes** (what shows, unsaved changes, the buttons, the list with Show / Delete). Wheel: a **Scenes** sub-wheel on the root ring (Default, Update, Save new, a wedge per scene).
  - **The glb's sub-assemblies** with no geometry of their own are now tagged with their `instance_path` too (`mesh_identity.gd`), so a scene can pose them; the appearance model keeps each occurrence's hidden flag.
  - **Not done:** hiding a part for a scene in VR (a shown scene's hidden flags are kept, nothing hides a part into one yet), drawing a scene's section planes (kept on Update, shown in the flat app), a viewpoint for a room's scene. Undo of Back to default puts the arrangement back but not the scene's hidden parts and looks.
- **Paint under a clip** (folded into M4 at the owner's request): an open room's clip and the section tool now keep a part's whole look, colour with see-through, metal, shine and glow (`scripts/clip_look.gd`, `shaders/section_clip_body.gdshaderinc`, a see-through variant `section_clip_alpha.gdshader`); a part split by appearance is wrapped surface by surface so each body and face keeps its look; a repaint while sectioning is wrapped again. Headless- and render-tested (`tests/clip_look.gd`, `tests/appearance_clip_render.gd`). The cut's inside face is still drawn 40% darker.
- **Appearance tool** (DIDSA-CAD `docs/appearance-tool-scope.md` V2; replaces the Colours page and the Paint gun, `colour_tool.gd` is gone; needs the DIDSA-CAD backend on the same branch). Headless-, render- and live-backend-tested; not checked on the headset.
  - **The gun:** with the tool on, a trigger **click** (down and up within 0.45 s) paints the **body** under the laser, on release (it used to paint the whole part on press). A **hold** of 0.45 s opens the paint breadcrumb at the hit point (built on `group_breadcrumb.gd`, now with a title and a swatch and "set here" note per row): **Face**, **Body** (lit), **Part**, **Pattern (all N)** for a pattern copy or source, **Every <part> (N)** when the part is placed more than once, each sub-assembly, **Whole assembly**. Hovering a row previews the result live (everything else keeps its own look), with brackets round what it paints, a haptic tick and its name on the wrist; letting go on a row paints it (one undo step); letting go off the panel paints nothing. Aiming lights the body a click would paint (a highlight, no paint colour). The assembly's own bodies can now be painted.
  - **Where paint goes:** an override in the assembly being worked in (the world's root, or a room's Part), never the placed parts' own files (`PUT /parts/{id}/appearance-overrides`). Painting a level that already has paint adds the brush's properties to it; **Clear** is a swatch that removes that level's paint. While **mates are relaxed** painting is temporary (nothing sent) and goes back on Return parts.
  - **The brush** (tablet: View > Appearance; replaces Colours / Paint): the palette and Clear, a hue ring + saturation / value square driven by the laser, Hex... on the keyboard, recent colours, the **eyedropper** (the next shot takes everything the face shows), **Opacity**, **Shine**, **Metal** and **Glow** sliders, each with a switch (only the switched-on properties are painted, so "opacity only" keeps the colour beneath), a live preview sphere wearing the real material, and saved appearances (six presets plus your own, kept in the settings). The tool wheel's palette ring gains Clear.
  - **Looks come from the glb:** the backend paints each part's material with the same rule (`scripts/appearance/appearance_rule.gd` is a copy of DIDSA-CAD's reference, checked against its 57 golden vectors); a part whose bodies or faces differ arrives as one primitive per look and `mesh_identity.gd` joins their face ids in surface order. After a paint the client restyles parts itself (`appearance_look.gd`: one material, or the mesh split into one surface per look with face ids and collider kept in step) until the next load.
  - **Pattern copies** now get a sub-assembly path (`group_index.gd` reads the glb's new `instance_path`), so they can be painted on their own. A group move of a patterned sub-assembly's copy is never saved onto its (non-existent) occurrence.
  - **Not done / limits:** (the clip shader's one-colour limit is fixed, see Paint under a clip above.) The hold's feel, the haptic tick, the picker's drag and the look of shine / metal / glow under the app's lighting are not checked on the headset.

## Unreleased (`main`, 14 Oct)

- **Relax all mates is a sandbox** (owner's design, 18 Oct; headless-tested, `tests/mates_sandbox.gd`; not on the headset or a live backend yet): turning Relax on remembers where every part is; then anything can be moved (grounded parts and mated sub-assemblies too) and nothing is saved or marks the document unsaved. Turning it off (**Return parts**) glides every remembered part back to exactly where it was, with no solve from the scattered layout, then solves only what mates made or edited meanwhile drive, from there. One undo step: undo puts your arrangement back and relaxes again. Enforce all while relaxed returns first. Parts that appear meanwhile (a file added, a room opened) keep their place and save their moves; deleted ones stay deleted; a reload while relaxed shows stored poses, which become the homes. Optional cues in Settings > Assemble, both off by default: a ghost where each moved part goes back to, and a line to it. The remembered poses are keyed by occurrence path (`sandbox_snapshot()`), the shape planned for saved scenes (not built; scoped in DIDSA-CAD `docs/scenes-scope.md`).
- **Tool wheel navigation** (18 Oct; headless-tested): rest 0.4 s on a sub-wheel's tile to open it where your hand is (an arc fills as the timer; moving out still works), rest in the middle of a sub-wheel to go back up one ring; letting go in the middle still cancels. The wrist panel's title is the path (Tools › Mates › Type). The Mates ring gains **Relax mates / Return parts**, and while relaxed the pill under every top-level ring is **Return parts**.

Hand travel is read in the ring's own tipped plane.
  - **Mates in multi-level assemblies** (Table Assy: Leg + Table Top with Frame > Frame > Frame A / B): Enforce all now re-applies the mates of every sub-assembly, deepest first, then the root's, and puts nested parts back where the stored tree places them. It used to try to solve a mate's path reference (`outer/inner/part`) as if it were a top-level occurrence, which the backend 404s: the "Couldn't satisfy every mate" error. A part that its sub-assembly's mates hold can no longer be moved on its own while mates are enforced (it moved on screen only and broke them); the same goes for a sub-assembly inside another that its parent's mates hold; the top-level sub-assembly can still be taken as a whole, and Relax all mates frees them. A mate naming a part that isn't in the assembly says so.
