## S4, sync hardening (DIDSA-CAD plan `mates-storage-sessions-plan-2026-11-12.md`, "S4. Hardening"; headless, Xvfb and against a real store that is killed and restarted, **not run on a headset**; details in `docs/server-projects.md`, "S4: hardening")

- **Chunked upload with resume**: a file over 90 MB, or one a tunnel refuses, goes up in 32 MB chunks through the store's new chunk routes, read from disk a chunk at a time; the session is kept in the private state so a cut connection, a store switched off or a closed app resumes where the store says it got to. A single big file is a one-file commit with its base version.

## S3, server projects (DIDSA-CAD plan `mates-storage-sessions-plan-2026-11-12.md`, "S3. VR"; scope `docs/shared-storage-scope.md` there; headless and against a real project store, **not run on a headset**; details in `docs/server-projects.md`)

- **A mirror folder per server project**: `Documents/DIDSA-Cloud/<server host>/<project>/`, visible and a sibling of `Documents/DIDSA` (not nested in it, not a dot-folder), so `native_compose.gd`, `file_lookup.gd`, `file_index.gd` and `project_save.gd` read and write it **unchanged** and the owner can drag files in by hand. The root is one setting (`[cloud] folder=` in `settings.cfg`); with *All files access* off, or a folder that can't be written, it falls back to `user://DIDSA-Cloud` and the Files page and the Servers page say so. The sync state (each file's version and hash as last synced, the queue of unsent saves, the change-feed cursor, the "mine" copies kept after Take theirs) is **private** (`user://didsa-cloud-state/`), so deleting the mirror cannot delete the queue; a queued save whose mirror file is gone is warned about.
- **Local changes are found by scanning the mirror** at sync time (SHA-256; modified time only skips re-hashing a file last changed before the previous scan): a file dropped in is a queued create (base version null), an edited one a queued edit, a removed one only "not downloaded" and **never a delete on the server**.
- **The flat app's rules and words (S2)**: a base version is not moved by a re-read (a file the open session holds is not refreshed under it); a single save is `PUT` with `If-Match` (a create `If-None-Match: *`; never a write without one), Save All is **one commit** (upload each file, then `POST .../commit`, all or nothing; a 409 writes nothing); 412 / 409 are per-file clashes with who changed it and when (`X-Device-Name`) and **Keep mine / Take theirs / Save mine as a copy** (`<name> (<device>, <date>).didsa` with a new document, Part and sketch id: `cloud_remint.gd`, a GDScript twin of `remint_identity.dart`, since VR had none); a deleted or moved file is a clash too; 401 names the store key, 413 and 400 show the store's message, an unreachable store queues the save, a file over 100 MB that fails while the store answers is explained as the tunnel's limit (no chunking: S4); a save equal to the version it was read at is not sent.
- **Sync**: the change feed from the saved cursor first (flags stale queued saves as clashes, refreshes files others changed, removes what the store removed from a clean mirror), then the queue as one commit; a refused cursor falls back to the tree. Runs when a project is opened, every 20 s while one is open, after Save, and on **Sync now**.
- **The moved-files rule against the store**: opening a file brings in what it places; a reference that doesn't resolve by path is looked up with `GET .../parts/{part_id}` (the tree's part ids when offline), not by reading files.
- **Screens**: wrist tablet > Files > **Server projects** (projects and files with a state symbol each: synced / to send / on the server only / not connected / clash; Keep mine / Take theirs / Save mine as a copy on the list; Sync now; New project), a line on Files > Models, a "Waiting to sync" / "Clash to settle" row on the landing, the Servers page's project store fields (add form and per saved server, **Store**), where the copy is, and this device's name (sent as `X-Device-Name`; default from the platform). `side_panel_ui.gd` rows can carry an `icon`; five cloud icons in `ui_icons.gd`.
- **Pairing**: the QR code's `p=<store address>` and `pk=<store key>` (not `s` / `sk`) are read and saved with the server; `secrets.cfg` may carry `[project_store]`. DIDSA-CAD's Connect a VR headset screen does not write them yet (the list is in `docs/server-projects.md`).
- Tests (new): `cloud_paths`, `cloud_remint`, `cloud_sync`, `cloud_moved_files`, `cloud_manager`, `cloud_ui` (a fake store, `tests/fake_project_store.gd`), and `e2e_cloud_store` against a real store (`tests/ci_e2e.sh` starts a throwaway one from DIDSA-CAD's `project-store/`; the e2e workflow installs its requirements). Adapted: none of the existing assertions changed.
- Not checked: anything on a headset (the permission, speed, how it reads, the laser on the new buttons), the owner's Pi, a Cloudflare tunnel, a synced Drive / NAS store root, killing the app mid-sync.

## Branch `m2-v8-limit-stop-caps` (13 Nov, not merged; DIDSA-CAD plan `docs/mates-storage-sessions-plan-2026-11-12.md`, M2)
